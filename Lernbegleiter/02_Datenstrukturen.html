Von null · §3.1Variable, Adresse, Zeiger
Prüfungsaufgabe (für sich allein lösbar). Gegeben: int a = 5; int *p = &a; *p = *p + 2; Die Variable a liegt bei Adresse 0x1000. Welchen Wert haben a, p und *p am Ende?
Lösung von null, Schritt für Schritt
1
Variable von null. Eine Variable ist eine benannte Speicherzelle. Der Name a steht für die Zelle bei 0x1000, ihr Inhalt ist zuerst 5.
2
Adresse. &a liefert die Adresse der Zelle, also 0x1000, nicht den Inhalt.
3
Zeiger. int *p ist eine Variable, die eine Adresse speichert. Nach p = &a steht in p die Zahl 0x1000.
4
Dereferenzieren. *p heißt „die Zelle, deren Adresse in p steht“, also a selbst. *p = *p + 2 liest 5 und schreibt 7 nach 0x1000.
5
Ergebnis. a = 7, p = 0x1000 (unverändert), *p = 7.
\[ \begin{aligned} \Mem{p} &= \Mem{\&}a = \texttt{0x1000} && \text{p enthält die Adresse.} \\ \Chg{*}\Mem{p} &= a && \text{Stern holt die Zelle.} \\ a &= 5 + 2 = \Res{7} && \text{über den Zeiger geschrieben.} \end{aligned} \]
✔ a = 7 · p = 0x1000 · *p = 7
§3.1 · Theorie Die drei Werkzeuge, aus denen alles gebaut wird
Basistypen int float char → struct bündelt Daten → Zeiger verweisen indirekt auf Daten.
Interface (.h)Deklariert Typ und Operationen: typedef int Number; Number randNum();. Ein Vertrag zwischen Client und Implementierung.
Implementierung (.cxx)Definiert die Funktionen: Number randNum() { return rand(); }. Sie bindet das eigene Interface mit ein, als Typprüfung.
ClientBenutzt nur das Interface (#include "Number.h"). Tauscht man die Implementierung, muss am Client nichts geändert werden.
Warum das wichtig ist: Sedgewick trennt ab hier immer Interface, Implementierung und Client. So kann man zwei Implementierungen (z.B. Stack als Array oder als Liste) mit demselben Client vergleichen. Das ist die Grundlage für jeden Laufzeitvergleich im Buch.
Anatomie Zeiger *, Adresse &, Referenz & im Speicher
Beobachte: *p = 7 ändert a, obwohl dort nie „a“ steht. Eine Referenz r ist nur ein zweiter Name für dieselbe Speicherzelle.
&aAdressoperator: liefert die Speicheradresse von a
int *pDeklaration: p ist ein Zeiger auf int, speichert also eine Adresse
*p = 7Dereferenzierung: „schreibe 7 dorthin, wohin p zeigt“
int &r = aReferenz: ein fest verbundener Zweitname, „ein Zeiger, der automatisch dereferenziert wird“
\[ \begin{aligned} \Mem{p} &= \Mem{\&}a && \text{p enthält die Adresse von a.} \\ \Chg{*}\Mem{p} &= a && \text{*p ist der Wert an dieser Adresse, also a selbst.} \\ \Chg{*}(\Mem{\&}a) &\equiv a && \text{* und \& heben sich gegenseitig auf.} \end{aligned} \]
void polar(float x, float y, float *r, float *theta)   // per Zeiger
  { *r = sqrt(x*x + y*y); *theta = atan2(y, x); }

  { r = sqrt(x*x + y*y); theta = atan2(y, x); }
// Aufruf: polar(1.0, 1.0, &a, &b);   bzw.   polar(1.0, 1.0, a, b);

Von null · §3.2Array: Adresse und Sieb
Prüfungsaufgabe (für sich allein lösbar). a) int a[20] beginnt bei 0x2000. Wo liegt a[7]? b) Welche Einträge setzt das Sieb des Eratosthenes (Prog 3.5) für N = 20 auf 0, und wie viele Schreibzugriffe sind das?
Lösung von null, Schritt für Schritt
1
Array von null. Ein Array ist ein zusammenhängender Block gleich großer Zellen. Die Adresse von a[i] ist Anfang + i · Größe einer Zelle; ein int hat 4 Byte. Deshalb kostet der Zugriff O(1).
2
Adresse. 0x2000 + 7 · 4 = 0x2000 + 28 = 0x201C.
3
Sieb, Idee. Alle Zahlen gelten zuerst als prim (a[i] = 1). Jede noch markierte Zahl i streicht ihre Vielfachen i·j mit j ≥ i.
4
i = 2. j = 2 … 9: streicht 4, 6, 8, 10, 12, 14, 16, 18 (8 Schreibzugriffe).
5
i = 3. j = 3 … 6: streicht 9, 12, 15, 18 (4 Schreibzugriffe). Ab i = 5 ist i·i ≥ 20, nichts mehr zu tun.
\[ \begin{aligned} \Mem{\&a[7]} &= \texttt{0x2000} + 7\cdot 4 = \texttt{0x201C} && \text{Anfang + Index mal Größe.} \\ \Chg{\text{Schreibzugriffe}} &= 8 + 4 = 12 && \text{Summe N/p über die Primzahlen p.} \\ \text{übrig} &= 2, 3, 5, 7, 11, 13, 17, 19 && \text{die Primzahlen unter 20.} \end{aligned} \]
✔ a[7] bei 0x201C · 12 Streichungen · Primzahlen 2 3 5 7 11 13 17 19
§3.2 · Theorie Array = zusammenhängender Speicher, Index = Adresse
„A fixed collection of same-type data stored contiguously and accessible by an index.“ Der ganze Speicher eines Rechners ist ein Array.
\[ \begin{aligned} \Mem{\&a[}\Idx{i}\Mem{]} &= \Mem{a} + \Idx{i}\cdot\texttt{sizeof(int)} && \text{Die Adresse lässt sich direkt berechnen.} \\ \text{Zugriff auf } a[i] &\in \Res{O(1)} && \text{Das ist ein Rechenschritt, egal wie groß } i \text{ ist.} \\ \text{Einfügen/Löschen in der Mitte} &\in \Res{O(N)} && \text{Alle Elemente dahinter müssen nachrücken.} \end{aligned} \]
Programmierer-Pflicht: Vor dem Lesen von a[i] muss dort etwas Sinnvolles stehen, und es muss \(0\le i<N\) gelten. C++ prüft beides nicht. Das sind die zwei häufigsten Array-Fehler (§3.2).
Prog 3.5 Sieb des Eratosthenes — Array-Zugriff per Index
Ziel: a[i] = 1 genau dann, wenn i prim ist. Für jede Primzahl i werden die Vielfachen i·j auf 0 gesetzt (Fig. 3.1).
IdeeEin Array von Ja/Nein-Markierungen. Jede noch markierte Zahl i ist prim und streicht ihre Vielfachen i·2, i·3, …
InvarianteWenn die äußere Schleife bei i ankommt, sind alle Zahlen unter i mit einem kleineren Primteiler schon gestrichen. Deshalb heißt a[i] == 1 dann: i ist prim.
KostenEtwa N ln N Schreibzugriffe, dank Index-Zugriff a[i*j] in O(1).
📖 Vorlesen: „Markiere alle Zahlen als prim. Gehe sie der Reihe nach durch. Ist eine noch markiert, streiche alle ihre Vielfachen. Am Ende sind die Primzahlen übrig.“
\[ \begin{aligned} \Res{T(N)} &\propto N && \text{Initialisierung und Ausgabe: je ein Durchlauf.} \\ &\quad + \tfrac N2 + \tfrac N3 + \tfrac N5 + \dots && \text{Je Primzahl } p \text{ werden } N/p \text{ Vielfache gestrichen.} \\ &< N\big(1+\tfrac12+\tfrac13+\dots+\tfrac1N\big) && \text{Abschätzung: über alle Zahlen statt nur über Primzahlen summieren.} \\ &= N\,H_N \approx \Res{N\ln N} && \text{Harmonische Zahl (Teil 1, Abschnitt 2.3).} \end{aligned} \]
Warum ein Array? Die innere Schleife springt in Schritten von i direkt zu a[i*j]. Mit einer Liste müsste man jedes Mal i*j Links weit laufen. Die äußere Schleife darf man nicht umdrehen, denn bevor a[i] geprüft wird, müssen alle kleineren Primzahlen ihre Vielfachen schon gestrichen haben. Die anderen Schleifen dürfen auch rückwärts laufen.

Prog 3.6 · Heap 
#include <iostream>                 // cout, endl
#include <stdlib.h>                 // atoi
using namespace std;
int main(int argc, char *argv[])      // argv[1] = N als Text von der Kommandozeile
  { int i, N = atoi(argv[1]);         // Text "1000" → Zahl 1000
    int *a = new int[N];              // Heap: N ints, Größe erst jetzt bekannt
    if (a == 0)                       // new hat keinen Speicher bekommen
      { cout << "out of memory" << endl; return 0; }
    for (i = 2; i < N; i++) a[i] = 1;             // zuerst: alle Kandidaten „prim“
    for (i = 2; i < N; i++)                       // für jede Zahl i …
      if (a[i])                                   // … die noch als prim gilt:
        for (int j = i; j*i < N; j++) a[i*j] = 0; //   ihre Vielfachen i·j streichen
    for (i = 2; i < N; i++)                       // Ausgabe
      if (a[i]) cout << " " << i;                //   nur die übrig gebliebenen
    cout << endl;
    delete[] a;                       // Heap-Speicher zurückgeben
  }

new int[N] liefert einen Zeiger auf den ersten von N ints. Freigeben mit delete[] a;. argv ist selbst ein Array von Strings (§3.7).

Prog 3.7 · Index aus Daten 
#include <iostream>
#include <stdlib.h>                       // rand, atoi
using namespace std;
int heads()                                 // ein Münzwurf:
  { return rand() < RAND_MAX/2; }           //   1 = Kopf, 0 = Zahl (je 50 %)
int main(int argc, char *argv[])
  { int i, j, cnt;
    int N = atoi(argv[1]);                  // Münzwürfe pro Experiment
    int M = atoi(argv[2]);                  // Anzahl der Experimente
    int *f = new int[N+1];                  // f[k] = wie oft genau k-mal Kopf
    for (j = 0; j <= N; j++) f[j] = 0;      // alle Zähler auf 0
    for (i = 0; i < M; i++, f[cnt]++)       // nach jedem Experiment: f[cnt] hochzählen
      for (cnt = 0, j = 0; j <= N; j++)     // ein Experiment: Münzen werfen …
        if (heads()) cnt++;                 //   … und die Köpfe zählen
    for (j = 0; j <= N; j++)                // Histogramm ausgeben, eine Zeile je k
      {
        if (f[j] == 0) cout << ".";         // nie vorgekommen: nur ein Punkt
        for (i = 0; i < f[j]; i += 10)      // je 10 Treffer ein Stern
          cout << "*";
        cout << endl;
      }
    delete[] f;
  }

Von null · §3.3Josephus mit einer zirkulären Liste
Prüfungsaufgabe (für sich allein lösbar). N = 5 Personen stehen im Kreis, jede M = 2. scheidet aus (Prog 3.9). In welcher Reihenfolge scheiden sie aus, wer bleibt übrig, wie viele Zeigerschritte sind es?
Lösung von null, Schritt für Schritt
1
Liste von null. Eine verkettete Liste besteht aus Knoten mit einem Wert und einem Link auf den nächsten Knoten. Zeigt der letzte wieder auf den ersten, ist sie zirkulär.
2
Entfernen in O(1). Steht x vor dem Opfer, genügt x->next = x->next->next. Es wird nichts verschoben, nur ein Link umgehängt.
3
Ablauf. x startet bei 5. Ein Schritt nach 1, entferne 2. Schritt nach 3, entferne 4. Schritt nach 5, entferne 1. Schritt nach 3, entferne 5.
4
Ergebnis. Reihenfolge 2, 4, 1, 5. Übrig bleibt 3.
\[ \begin{aligned} \text{Runden} &= N - 1 = 4 && \text{bis einer übrig ist.} \\ \text{Schritte} &= (N-1)(M-1) = 4 && \text{Weiterzählen.} \\ \Res{T} &= 4 + 4 = 8 && \text{plus ein Umhängen pro Runde.} \end{aligned} \]
✔ Reihenfolge 2 4 1 5 · Überlebender 3 · 8 Schritte
§3.3 · Theorie Knoten = Item + Link auf Knoten (selbstbezüglich)
Def. 3.2: „A linked list is a set of items where each item is part of a node that also contains a link to a node.“
VorteilUmordnen ist billig: Einfügen und Entfernen kosten nur 2 Zeigerzuweisungen, egal wie lang die Liste ist. „The raison d'être of linked lists.“
NachteilKein direkter Zugriff: Für das k-te Element muss man k Links folgen. Auch „finde den Vorgänger“ ist in einer einfach verketteten Liste unnatürlich.
Fig 3.3 · 3.4 Entfernen und Einfügen, jeweils 2 Zeilen
Wähle die Operation und gehe die Zeigerzuweisungen einzeln durch. Die orangefarbenen Links ändern sich gerade.
IdeeEine Liste ändert man, indem man Links umbiegt. Dabei wird kein Element verschoben.
InvarianteJeder Knoten ist von head aus erreichbar, und zwar nach jeder einzelnen Zuweisung, wenn die Reihenfolge stimmt.
Kosten2 Zuweisungen, also O(1), egal wie lang die Liste ist.
📖 Vorlesen: „Beim Löschen merkt man sich den Knoten und lässt x ihn überspringen. Beim Einfügen hängt man zuerst t an den Rest und erst dann x an t.“
\[ \begin{aligned} &\textbf{Entfernen nach } x\textbf{:} && \\ \Idx{t} &\Chg{=} x\Mem{\to next} && \text{t merkt sich den Knoten, der verschwinden soll.} \\ x\Mem{\to next} &\Chg{=} \Idx{t}\Mem{\to next} && \text{x überspringt ihn.} \\ &\textbf{Einfügen von } t \textbf{ nach } x\textbf{:} && \\ t\Mem{\to next} &\Chg{=} x\Mem{\to next} && \text{Zuerst hängt t sich an den Rest.} \\ x\Mem{\to next} &\Chg{=} t && \text{Dann zeigt x auf t.} \\ \text{Kosten} &= \Res{O(1)} && \text{Je 2 Zuweisungen, unabhängig von der Listenlänge.} \end{aligned} \]
Reihenfolge beim Einfügen ist entscheidend: Setzt man zuerst x->next = t, ist der Rest der Liste verloren (niemand zeigt mehr darauf). Deshalb zuerst den neuen Knoten an den Rest hängen, dann umbiegen. Beim Entfernen merkt sich t den Knoten, damit man ihn danach mit delete t freigeben kann.
Prog 3.9 Josephus-Problem mit zirkulärer Liste
N Personen im Kreis, jede M-te scheidet aus. Wer bleibt übrig? Für N = 9, M = 5 ist die Reihenfolge 5 1 7 4 3 6 9 2, und 8 gewinnt (Fig. 3.5).
IdeeDie Personen sitzen in einer zirkulären Liste. Zählen heißt Links folgen, Ausscheiden heißt einen Link überspringen.
Invariantex zeigt immer auf die Person vor der nächsten, die gezählt wird. Deshalb kann man x->next in O(1) entfernen.
Kosten(N−1)·(M−1) Zählschritte plus N−1 Entfernungen, also O(N·M).
📖 Vorlesen: „Baue einen Kreis aus N Knoten. Solange mehr als einer übrig ist: gehe M−1 Schritte weiter und entferne den nächsten Knoten. Der letzte Knoten ist der Gewinner.“
Aufbau (Z. 11–14)Ein Knoten 1, der auf sich selbst zeigt (t->next = t). Dann wird jeder neue Knoten hinter x eingefügt und zeigt zurück auf t. So bleibt der Kreis immer geschlossen.
Zählen (Z. 17)x = x->next läuft M−1 Schritte. Danach ist x->next die M-te Person.
Entfernen (Z. 18)x->next = x->next->next überspringt die Person in O(1). Mit einem Array müsste man alle Nachfolger nachrücken lassen.
\[ \begin{aligned} \text{Runden} &= \Idx{N-1} && \text{So lange, bis nur eine Person übrig ist.} \\ \text{Schritte je Runde} &= \Par{M-1} && x = x\to next \text{ zählt weiter.} \\ \text{Entfernen je Runde} &= O(1) && \text{Ein einziger Link wird umgehängt.} \\ \Res{T(N,M)} &= (N-1)(M-1) + (N-1) = \Res{O(NM)} && \text{Summe über alle Runden.} \end{aligned} \]
Fig. 3.6 (Liste mit Array-Indizes): Rechts im Tracer siehst du dieselbe Liste als Array next[]. Weil Person i im Index i steht, ist next[i] die nächste Person. Eine Liste ist eine Abstraktion, und C++-Zeiger sind nur eine Implementierung davon.

§3.4 · Theorie Die rekursive Sicht und die Standard-Schleife
Def. 3.3: „A linked list is either a null link or a link to a node that contains an item and a link to a linked list.“
\[ \begin{aligned} \Rule{\text{Liste}} &::= \Cond{0} && \text{Entweder leer (Null-Link, der Anker)} \\ &\;\;\;\big|\;\; \Mem{\text{Knoten}}(\Par{\text{item}},\ \Rule{\text{Liste}}) && \text{oder ein Knoten, dessen Link wieder auf eine Liste zeigt.} \end{aligned} \]
for (link t = x; t != 0; t = t->next) visit(t->item);   // Traversierung: so häufig wie for (i=0;i<N;i++)
Häufigste Listen-Fehler: ein undefinierter Zeiger (das Gegenstück zum Array-Index außerhalb der Grenzen) und ein Zeiger, der unbemerkt verändert wurde, weil zwei Links auf denselben Knoten zeigen. Deshalb zeichnet man Listen-Code immer als Bild wie Fig. 3.7.
Prog 3.10 Liste umkehren mit drei Zeigern
r = schon umgedrehter Teil, y = noch nicht gesehener Teil, t = Zwischenspeicher für y->next. Der Rumpf ist zur Schrittweise-Anzeige auf 4 Zeilen verteilt, der Code ist derselbe.
IdeeMan läuft einmal durch die Liste und dreht dabei jeden Link um.
Invarianter ist immer eine korrekt umgedrehte Liste der schon besuchten Knoten, y der unveränderte Rest. Zusammen enthalten sie alle Knoten.
Kosten4 Zuweisungen je Knoten, also O(N) Zeit und O(1) Zusatzspeicher.

§3.5 · Theorie Die Freiliste ist selbst eine verkettete Liste
Sind alle Knoten gleich groß, kann man freie Knoten einfach auf einer Liste sammeln. newNode nimmt vorne einen weg, deleteNode legt ihn vorne wieder drauf, jeweils in O(1).
link freelist;
void construct(int N)
  { freelist = new node[N+1];                 // alle Knoten auf einmal
    for (int i = 0; i < N; i++)
      freelist[i].next = &freelist[i+1];      // zu einer Liste verketten
    freelist[N].next = 0;
  }
link newNode(int i)  { link x = remove(freelist); x->item = i; x->next = x; return x; }
void deleteNode(link x) { insert(freelist, x); }
void insert(link x, link t) { t->next = x->next; x->next = t; }
link remove(link x) { link t = x->next; x->next = t->next; return t; }
Warum ein eigener Allokator? Ein allgemeines new muss Blöcke beliebiger Größe verwalten und ist deshalb komplizierter und langsamer. Wer weiß, dass alle Anfragen gleich groß sind, kann das ausnutzen.   { int X = x*G+1; int Y = y*G+1;
    point p; p.x = x; p.y = y;

class UF
  {
    private:
      int *id, *sz;
      int find(int x)                                   // private Hilfsfunktion (überladen)
        { while (x != id[x]) x = id[x]; return x; }
    public:
      UF(int N)
        {

          for (int i = 0; i < N; i++)

        { return (find(p) == find(q)); }

        { int i = find(p), j = find(q);
          if (i == j) return;
          if (sz[i] < sz[j])
               { id[i] = j; sz[j] += sz[i]; }
          else { id[j] = i; sz[i] += sz[j]; }
        }
  };

§5.1 · Theorie Rekursion = Induktionsbeweis, der rechnet, und darunter ein Stack
„A recursive program cannot call itself always, or it would never stop.“ Jede rekursive Funktion braucht zwei Dinge:
① Rekursionsanker (Basisfall)wird direkt gelöst, ohne weiteren Aufruf: if (N == 0) return 1;. Das entspricht dem Induktionsanfang.
② Jeder Aufruf mit kleinerem Argumentreturn N*factorial(N-1);. Das entspricht dem Induktionsschritt. Ohne „kleiner“ gibt es keinen Beweis, dass das Programm endet (Prog 5.2).
\[ \begin{aligned} \Res{N!} &= \Cond{1} && \text{falls } \Cond{N = 0} \text{ (Anker),} \\ \Res{N!} &= \Par{N}\cdot\Res{(N-1)!} && \text{falls } N \ge 1 \text{ (Rückführung auf das kleinere Problem).} \\ &\Longleftrightarrow\ \texttt{factorial(N)} && \text{Programm 5.1 schreibt genau diese Definition ab.} \end{aligned} \]
Die versteckten Kosten: Jeder Aufruf legt einen Stackframe (Argumente, lokale Variablen, Rücksprungadresse) auf den eingebauten Pushdown-Stack. Die Rekursionstiefe ist die maximale Schachtelung und damit der Speicherbedarf dieses Stacks. Bei factorial(N) sind das N+1 Frames. Jede Rekursion lässt sich in eine Schleife mit explizitem Stack umwandeln und umgekehrt.
Prog 5.1 Fakultät: Aufrufstapel wächst, dann wird zurückgerechnet
Rechts siehst du den Aufrufstapel. Oben liegt der aktive Frame, rot steht der Rückgabewert, sobald er feststeht.
IdeeN! wird auf (N−1)! zurückgeführt, bis der Anker 0! = 1 erreicht ist.
InvarianteJeder Aufruf mit N ≥ 1 ruft sich mit einem echt kleineren Argument auf, also endet die Rekursion.

Prog 5.7 Türme von Hanoi
Um N Scheiben einen Stab nach rechts zu schieben: N−1 Scheiben nach links, Scheibe N nach rechts, dann N−1 Scheiben wieder nach links (auf Scheibe N). Die Richtung ist zyklisch: +1 heißt rechts, −1 heißt links.
IdeeUm N Scheiben zu bewegen, muss die größte einmal frei liegen. Also erst N−1 Scheiben weg, dann die größte, dann N−1 zurück darauf.
InvarianteEine größere Scheibe liegt nie auf einer kleineren, weil Scheibe N erst bewegt wird, wenn alle kleineren auf dem dritten Stab liegen.
KostenM(N) = 2·M(N−1) + 1, also 2^N − 1 Züge (Eigenschaft 5.2).
📖 Vorlesen: „Bewege die N−1 kleineren in die andere Richtung, schiebe Scheibe N, und bewege die N−1 kleineren wieder in die andere Richtung.“
\[ \begin{aligned} &\textbf{Eigenschaft 5.2:} && \\ \Res{M_N} &= 2\,M_{N-1} + 1 && \text{Zweimal den Turm aus } N-1 \text{ Scheiben bewegen, plus 1 Zug für die größte.} \\ \Cond{M_1} &\Cond{= 1} && \text{Eine Scheibe braucht einen Zug.} \\ \Res{M_N} &= 2^N - 1 && \text{Lösung (Beweis per Induktion unten).} \\ N = 40 &\Rightarrow\ > 348 \text{ Jahrhunderte} && \text{bei einem Zug pro Sekunde.} \end{aligned} \]
Beweis per Induktion: \(M(1)=2^1-1=1\). Gilt \(M(k)=2^k-1\) für \(k<N\), dann ist \(M(N)=2(2^{N-1}-1)+1=2^N-1\). Das ist Formel 2.5 in anderer Gestalt. Die Folge der bewegten Scheiben ist exakt dieselbe wie die Folge der Lineal-Markierungen (Prog 5.8) und wie die Anzahl der Endnullen in der Binärdarstellung von 1, 2, 3, … (Fig. 5.9). Nicht-rekursives Rezept: abwechselnd die kleinste Scheibe bewegen und den einzigen anderen erlaubten Zug machen.
Prog 5.8 · 5.9 Ein Lineal zeichnen: rekursiv (in Reihenfolge) und bottom-up

    if (h > 0)

        rule(l, m, h-1);
        mark(m, h);
        rule(m, r, h-1);
      }

Prog 5.9 · bottom-up (ohne Rekursion)
void rule(int l, int r, int h)
  {
    for (int t = 1, j = 1; t <= h; j += j, t++)
      for (int i = 0; l+j+i <= r; i += j+j)
        mark(l+j+i, t);
  }
Drei Programme, dasselbe Bild, verschiedene Reihenfolge. Inorder zeichnet von links nach rechts (gut für ein „endloses“ Lineal). Beim bottom-up-Verfahren kommen zuerst alle kurzen Marken, dann alle der Länge 2 usw. Diese Methode heißt combine and conquer. Die Länge der Marke an Position i ist die Anzahl der Endnullen von i in Binärdarstellung, plus 1.

Prog 5.12 · 5.13 Rucksackproblem (Fig. 5.16)
Gegenstände A–E mit (Größe, Wert) = (3,4) (4,5) (7,10) (8,11) (9,13), unbegrenzt viele von jeder Sorte. Welche Füllung von Kapazität M hat maximalen Wert?
int knap(int M)
  { int i, space, max, maxi = 0, t;
    if (maxKnown[M] != unknown) return maxKnown[M];      // Memo
    for (i = 0, max = 0; i < N; i++)
      if ((space = M-items[i].size) >= 0)                // passt Item i?
        if ((t = knap(space) + items[i].val) > max)      // i + bester Rest
          { max = t; maxi = i; }
    maxKnown[M] = max; itemKnown[M] = items[maxi];
    return max;
  }
\[ \begin{aligned} \Res{\text{knap}(M)} &= \max_{\Idx{i}:\ \text{size}_i \le M} \big(\text{val}_i + \Res{\text{knap}}(M-\text{size}_i)\big) && \text{Jedes passende Item als erstes probieren, den Rest optimal füllen.} \\ \text{knap}(0) &= 0 && \text{Ein leerer Rucksack hat Wert 0.} \\ \text{Laufzeit mit DP} &= \Res{O(N\cdot M)} && M \text{ Kapazitäten, für jede } N \text{ Items probieren.} \end{aligned} \]
Prinzip der optimalen Teilstruktur: „Optimal decisions, once made, do not need to be changed.“ Die beste Füllung von M setzt sich aus einem Item und der besten Füllung des Restes zusammen. Die Tabelle zeigt maxKnown[m] für alle m ≤ M. Grün markiert ist der Pfad über itemKnown, der die Lösung rekonstruiert. Grenze: Bei riesigem M (etwa 64-Bit-Größen) passt die Tabelle nicht in den Speicher, und dann hilft DP nicht mehr (Teil 8, NP-Vollständigkeit).

Prüfungsaufgabe (für sich allein lösbar). Ein Binärbaum hat drei innere Knoten: eine Wurzel mit zwei Kindern. Berechne die innere Pfadlänge I, die äußere Pfadlänge E und prüfe E = I + 2N.

2

3
E. Jedes Kind hat zwei externe Knoten der Tiefe 2: 4 · 2 = 8.
4
Probe. I + 2N = 2 + 6 = 8 = E.
\[ \begin{aligned} I &= 0 + 1 + 1 = 2 && \text{innere Knoten.} \\ E &= 4\cdot 2 = 8 && \text{externe Knoten.} \\ E &= I + 2N && \text{Eigenschaft 5.7.} \end{aligned} \]
✔ I = 2 · E = 8 = I + 2N
Baum-Labor Baue einen Binärbaum und prüfe die Eigenschaften live
Klicke einen externen Knoten □ an: Er wird zu einem inneren Knoten mit zwei neuen externen Kindern. Genau so beweist Sedgewick Eigenschaft 5.7.
\[ \begin{aligned} &\textbf{5.5:}\;\; \#\Mem{\text{extern}} = \Par{N}+1 && \text{Es gibt einen externen Knoten mehr als innere.} \\ &\textbf{5.6:}\;\; 2N = (N-1) + (N+1) && \text{Links: } N-1 \text{ zu inneren, } N+1 \text{ zu externen Knoten.} \\ &\textbf{5.7:}\;\; \Res{E} = \Res{I} + 2\Par{N} && \text{Äußere Pfadlänge = innere Pfadlänge + } 2N. \\ &\textbf{5.8:}\;\; \lg N \le \text{Höhe} \le N-1 && \text{Von balanciert bis entartet.} \\ &\textbf{5.9:}\;\; N\lg\tfrac N4 \le \Res{I} \le \tfrac{N(N-1)}{2} && \text{Schranken für die innere Pfadlänge.} \end{aligned} \]
Beweis 5.5/5.7 (Konstruktion)Start: ein externer Knoten, I = E = 0. Jeder Schritt ersetzt einen externen Knoten auf Ebene k durch einen inneren: I wächst um k, E um −k + 2(k+1) = k+2. Nach N Schritten ist \(E - I = 2N\), und die Zahl der externen Knoten steigt pro Schritt um 1, also \(N+1\).

Wo ist Fädelung sinnvoll? □ hohler Baum (Daten nur in Blättern) □ Binärbaum (Daten in Blättern und Knoten) □ doppelt verkettete Liste
Lösung Schritt für Schritt
1
Was ist Fädelung? Ein gefädelter (threaded) Baum nutzt Zeiger, die sonst leer wären, als „Fäden“ zum Nachfolger (bzw. Vorgänger) in der Durchlaufreihenfolge. Dann kann man ohne Stack und ohne Rekursion traversieren (§5.6 braucht sonst einen Stack oder Rekursion).
2
Binärbaum. Ein Binärbaum mit n Knoten hat n + 1 leere Links (Eigenschaft 5.4 aus Teil 2). Sie kosten Platz, tragen aber keine Information. Als Fäden zum Inorder-Nachfolger machen sie den Durchlauf billig. ✓
3
Hohler Baum. Im hohlen Baum stehen die Daten nur in den Blättern (wie im B⁺-Baum aus §16.3). Verkettet man die Blätter der Reihe nach, kann man alle Daten sortiert durchlaufen und Bereichsanfragen beantworten, ohne wieder nach oben zu steigen. Das ist Fädelung der Blattebene. ✓
4
Doppelt verkettete Liste. Hier hat jedes Element schon Zeiger auf Vorgänger und Nachfolger. Es gibt nichts zu fädeln. ✗
✔ hohler Baum ✓ · Binärbaum ✓ · doppelt verkettete Liste ✗ (keine offizielle Lösung; Begründung oben)

\[ \begin{aligned} \Res{\text{count}(h)} &= \Cond{0} && \text{Leerer Baum (Anker).} \\ \Res{\text{count}(h)} &= \text{count}(l)+\text{count}(r)+1 && \text{Sonst: beide Teilbäume plus die Wurzel.} \\ \Res{\text{height}(h)} &= \Cond{-1} && \text{Leerer Baum (Anker).} \\ \Res{\text{height}(h)} &= \max(\text{height}(l),\text{height}(r))+1 && \text{Sonst: der höhere Teilbaum plus eine Ebene.} \end{aligned} \]
Prog 5.19 · 5.20 Bäume bauen: Turnier und Parse-Baum
Turnier (5.19) aus A M P L E
link max(Item a[], int l, int r)
  { int m = (l+r)/2;
    link x = new node(a[m]);
    if (l == r) return x;
    x->l = max(a, l, m);
    x->r = max(a, m+1, r);
    Item u = x->l->item, v = x->r->item;
    if (u > v) x->item = u; else x->item = v;
    return x;
  }

Jeder innere Knoten ist eine Kopie des größeren Kindes, deshalb steht das Maximum an der Wurzel. Zwei Turniere lassen sich in O(1) verbinden. Das ist die Vorstufe der Priority Queues (Kap. 9).

Parse-Baum (5.20)
char *a; int i;
struct node
  { Item item; node *l, *r;
    node(Item x) { item = x; l = 0; r = 0; } };
typedef node* link;
link parse()
  { char t = a[i++]; link x = new node(t);
    if ((t == '+') || (t == '*'))
      { x->l = parse(); x->r = parse(); }
    return x;
  }

Präfix * + a * * b c + d e f: Operatoren werden innere Knoten, Operanden Blätter. Mit Inorder erhält man Infix, mit Postorder Postfix, und über Postorder erzeugt ein Compiler auch den Maschinencode.

§5.8

Graph-Traversierung: DFS und BFS

Prog. 5.21 Tiefensuche · 5.22 Breitensuche · Eigenschaft 5.10
Von null · §5.8Tiefensuche und Breitensuche
Prüfungsaufgabe (für sich allein lösbar). Graph mit den Kanten 0-1, 0-2, 1-3, 2-3, 3-4, Adjazenzlisten aufsteigend. In welcher Reihenfolge besuchen DFS (Prog 5.21) und BFS (Prog 5.22) die Knoten ab 0?
Lösung von null, Schritt für Schritt
1
Graph von null. Ein Graph besteht aus Knoten und Kanten. Die Adjazenzliste eines Knotens nennt seine Nachbarn: 0: 1 2 · 1: 0 3 · 2: 0 3 · 3: 1 2 4 · 4: 3.
2
DFS. Tiefe zuerst mit Rekursion (also einem Stack): 0, dann erster unbesuchter Nachbar 1, von dort 3, von dort 2, zurück zu 3, dann 4. Reihenfolge 0 1 3 2 4.
3
BFS. Breite zuerst mit einer Queue: 0 besuchen, 1 und 2 anstellen. 1 besuchen, 3 anstellen. 2 besuchen (3 noch einmal anstellen). 3 besuchen, 4 anstellen. Das doppelte 3 wird übersprungen, dann 4. Reihenfolge 0 1 2 3 4.
4
Markieren. visited[] verhindert, dass ein Knoten zweimal besucht wird, auch bei Kreisen wie 0-1-3-2-0.
\[ \begin{aligned} \text{Zeit} &\propto V + E && \text{Eigenschaft 5.10: jeder Kopf und jeder Listenknoten einmal.} \end{aligned} \]
✔ DFS 0 1 3 2 4 · BFS 0 1 2 3 4
Prog 5.21 · 5.22 Tiefensuche (rekursiv) und Breitensuche (Queue) auf dem Graphen aus §3.7
Adjazenzlisten wie in Fig. 5.32: 0 → 7 5 2 1 6 · 1 → 7 0 · 2 → 7 0 · 3 → 5 4 · 4 → 6 5 7 3 · 5 → 0 4 3 · 6 → 4 0 · 7 → 1 2 0 4.
IdeeDFS geht mit Rekursion so tief wie möglich. BFS stellt Nachbarn in eine Queue und arbeitet Ebene für Ebene ab.
Invariantevisited[k] == 1 heißt: k wurde schon besucht. Deshalb wird kein Knoten zweimal besucht, auch bei Kreisen im Graphen.
KostenMit Adjazenzlisten Zeit ∝ V + E (Eigenschaft 5.10).
📖 Vorlesen: „Besuche den Knoten und markiere ihn. Gehe dann seine Nachbarliste durch. Bei DFS sofort rekursiv zu jedem unbesuchten, bei BFS hinten in die Queue.“
DFS · Prog 5.21
void traverse(int k, void visit(int))
  { visit(k); visited[k] = 1;
    for (link t = adj[k]; t != 0; t = t->next)
      if (!visited[t->v]) traverse(t->v, visit);
  }
Ein Sucher geht so tief wie möglich und kehrt erst an Sackgassen um. Die befolgten Kanten bilden den DFS-Baum, einen Spannbaum. Ist der Graph ein Baum, ist DFS dasselbe wie Preorder.
BFS · Prog 5.22
void traverse(int k, void visit(int))
  { QUEUE<int> q(V*V);
    q.put(k);
    while (!q.empty())
      if (visited[k = q.get()] == 0)
        { visit(k); visited[k] = 1;
          for (link t = adj[k]; t != 0; t = t->next)
            if (visited[t->v] == 0) q.put(t->v);
        }
  }
Eine „Armee von Suchern“ fächert Ebene für Ebene auf. Tauscht man die Queue gegen einen Stack, erhält man eine DFS-ähnliche Suche. Jede verallgemeinerte Queue besucht alle Knoten.
\[ \begin{aligned} &\textbf{Eigenschaft 5.10:} && \\ \text{DFS mit Adjazenzlisten} &\propto \Res{V+E} && \text{Die Zeit setzt sich aus zwei Teilen zusammen:} \\ &\phantom{\propto}\ V && \text{Jeder Listenkopf wird einmal angefasst,} \\ &\phantom{\propto}\ + 2E && \text{jeder Listenknoten höchstens einmal (jede Kante steht in 2 Listen).} \end{aligned} \]
Zurück zu Kapitel 1: DFS löst das Konnektivitätsproblem in linearer Zeit \(V+E\). Union-Find braucht aber nur Speicher \(\propto V\) statt \(\propto E\) und verarbeitet die Kanten online. Bei riesigen Graphen gewinnt deshalb oft Union-Find. So schließt sich der Kreis zu Teil 1.
