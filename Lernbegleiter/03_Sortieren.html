Master-Anatomie Jedes Sortierverfahren = Invariante + Vergleich + Bewegung
Alle Programme in Kap. 6–9 benutzen nur zwei Grundoperationen: einen Vergleich zweier Schlüssel und eine Bewegung (Tausch oder Zuweisung). Die Kosten sind deshalb die Anzahl dieser beiden Operationen.
template <class Item>
  void exch(Item &A, Item &B)          // Tausch: 3 Zuweisungen über einen Zwischenspeicher t
    { Item t = A; A = B; B = t; }
template <class Item>
  void compexch(Item &A, Item &B)      // Vergleich und, falls nötig, Tausch
    { if (B < A) exch(A, B); }         // danach gilt immer: A ≤ B
B < AVergleich: die einzige Stelle, an der ein Verfahren etwas über die Schlüssel erfährt. Ihre Anzahl ist \(\Res{C_N}\).
exch(A, B)Tausch: Zwei Elemente wechseln den Platz. Insertion Sort und Shellsort verschieben stattdessen mit einer einzigen Zuweisung (half-exchange).
InvarianteWas nach jedem Schleifendurchlauf wahr bleibt: „links von i ist alles fertig“ (Selection), „links von i ist sortiert“ (Insertion), „links vom Pivot kleiner, rechts größer“ (Quicksort), „Heap-Ordnung“ (Heapsort). Die Invariante beweist die Korrektheit.
a[l] … a[r]Konvention des Buchs: Jede Funktion sortiert den Teilbereich von Index l bis einschließlich r, also \(N = r - l + 1\) Elemente.

§6.1 · Theorie Was „Sortieren“ genau heißt
„The objective of the sorting method is to rearrange the items such that their keys are ordered according to some well-defined ordering rule.“
Item und KeyEin Item ist der ganze Datensatz, der Schlüssel (key) nur der Teil, nach dem sortiert wird. Oft ist der Schlüssel klein und der Datensatz groß, und genau das entscheidet später, ob Vergleiche oder Bewegungen teurer sind.
intern vs. externPasst die Datei in den Speicher, ist das Sortieren intern und jeder Zugriff kostet gleich viel. Liegt sie auf Band oder Platte, ist es extern und man darf nur sequentiell oder blockweise lesen (Kap. 11).
Array oder ListeBeide sind interessant. Manche Verfahren passen zu beiden (Selection, Mergesort), andere brauchen Direktzugriff per Index (Shellsort, Heapsort).
\[ \begin{aligned} \text{Laufzeit} &\propto \Res{\text{Vergleiche}} && \text{wenn die Schlüssel groß oder teuer zu vergleichen sind,} \\ \text{Laufzeit} &\propto \Chg{\text{Bewegungen}} && \text{wenn die Datensätze groß sind,} \\ \text{Speicher} &= N + \Mem{\text{extra}} && \text{extra} = 0 \text{ (in-place)}, \ \lg N \text{ (Stack) oder } N \text{ (Hilfsarray).} \end{aligned} \]
Drei Fragen an jedes Verfahren: Wie viele Vergleiche und Bewegungen braucht es (im Mittel und im schlechtesten Fall)? Wie viel zusätzlicher Speicher? Ist es stabil, lässt es also gleiche Schlüssel in ihrer ursprünglichen Reihenfolge?
Prog 6.1 Ein vollständiges Sortierprogramm mit Treiber
Der Treiber erzeugt N Zufallszahlen (oder liest sie ein), ruft sort auf und gibt das Ergebnis aus. Die Sortierfunktion ist eine einfache, nicht-adaptive Variante von Insertion Sort.
#include <iostream>
#include <stdlib.h>
using namespace std;
template <class Item>
  void exch(Item &A, Item &B)
    { Item t = A; A = B; B = t; }             // Tausch über t
template <class Item>
  void compexch(Item &A, Item &B)
    { if (B < A) exch(A, B); }                // danach: A ≤ B
template <class Item>
  void sort(Item a[], int l, int r)
    { for (int i = l+1; i <= r; i++)          // Element i einsortieren,
        for (int j = i; j > l; j--)           // und zwar immer bis ganz nach links
          compexch(a[j-1], a[j]);             // Nachbarn ordnen
    }
int main(int argc, char *argv[])
  { int i, N = atoi(argv[1]), sw = atoi(argv[2]);   // N Zahlen; sw = 1: zufällig, 0: einlesen
    int *a = new int[N];
    if (sw)
      for (i = 0; i < N; i++)
        a[i] = 1000*(1.0*rand()/RAND_MAX);         // Zufallszahl zwischen 0 und 1000
    else
      { N = 0; while (cin >> a[N]) N++; }          // von der Standardeingabe lesen
    sort(a, 0, N-1);                                // ganzes Array a[0..N-1] sortieren
    for (i = 0; i < N; i++) cout << a[i] << " ";
    cout << endl;
  }
IdeeFür jedes i wird das neue Element durch Nachbar-Vergleiche so weit nach links geschoben, bis es passt. Die innere Schleife läuft aber immer bis l, auch wenn nichts mehr zu tun ist.
InvarianteNach Runde i ist a[l..i] sortiert.
KostenGenau N(N−1)/2 compexch-Aufrufe, unabhängig von der Eingabe: nicht adaptiv.
📖 Vorlesen: „Für jedes i von l+1 bis r vergleiche und tausche benachbarte Elemente von i nach links bis l. Danach ist der Bereich bis i sortiert.“
\[ \begin{aligned} \Res{C_N} &= \sum_{i=l+1}^{r} (i - l) && \text{In Runde } i \text{ läuft } j \text{ von } i \text{ bis } l+1, \text{ das sind } i-l \text{ Vergleiche.} \\ &= 1 + 2 + \dots + (N-1) && \text{Mit } N = r-l+1. \\ &= \Res{\frac{N(N-1)}{2}} && \text{Gauß-Summe, und zwar für jede Eingabe gleich.} \end{aligned} \]
Warum Templates? sort braucht von Item nur zwei Dinge: den Vergleich < und die Zuweisung. Damit sortiert derselbe Code int, float, Strings oder Datensätze (§6.7).
§6.2

Selection Sort

Prog. 6.2 · Fig. 6.2 · Eigenschaft 6.1 · 6.6
Prog 6.2 Selection Sort: immer das kleinste Restelement nach vorne
„First, find the smallest element in the array, and exchange it with the element in the first position. Then, find the second smallest element and exchange it with the element in the second position.“ Beispiel aus Fig. 6.2: A S O R T I N G E X A M P L E.
IdeeSuche im unsortierten Rest das Minimum und tausche es an die Stelle i. Dann ist Stelle i endgültig fertig.
Invariantea[l..i−1] enthält die i−l kleinsten Elemente in sortierter Reihenfolge, und keines davon wird je wieder angefasst.
KostenImmer ≈ N²/2 Vergleiche, aber nur N−1 Tausche (Eigenschaft 6.1).
📖 Vorlesen: „Für jede Stelle i: merke dir i als bisheriges Minimum, laufe mit j über den Rest und merke dir jedes kleinere Element. Am Ende tausche das Minimum an die Stelle i.“
min = iKandidat für das Minimum ist zuerst das Element an Stelle i selbst
a[j] < a[min]der einzige Vergleich. Er läuft für jedes Paar (i, j) mit j > i genau einmal
exch(a[i], a[min])genau ein Tausch pro Runde, auch wenn min == i (dann tauscht das Element mit sich selbst)
\[ \begin{aligned} &\textbf{Eigenschaft 6.1:} && \\ \Res{C_N} &= \sum_{i=0}^{N-2} (N-1-i) && \text{In Runde } i \text{ vergleicht } j \text{ die Stellen } i+1 \text{ bis } N-1. \\ &= (N-1) + (N-2) + \dots + 1 && \text{Die Summe rückwärts gelesen.} \\ &= \Res{\frac{N(N-1)}{2} \approx \frac{N^2}{2}} && \text{Gauß-Summe.} \\ \Chg{M_N} &= \Chg{N-1} && \text{Ein Tausch pro Runde, die letzte Stelle ist automatisch richtig.} \\ \#\,\texttt{min = j} &\le \frac{N^2}{2}, \text{ im Mittel } O(N\log N) && \text{Nur dieser Teil hängt von der Eingabe ab.} \end{aligned} \]
NachteilDie Laufzeit hängt fast nicht von der Eingabe ab. Auch eine schon sortierte Datei kostet N²/2 Vergleiche, weil der erste Durchlauf nichts über den zweiten verrät.
Eigenschaft 6.6: Vorteil bei großen DatensätzenKostet ein Vergleich 1 und ein Tausch M Zeiteinheiten, dann gilt: Vergleiche ≈ N²/2, Tausche ≈ N·M. Ist M groß (etwa M ≥ c·N), dominiert der Term N·M. Das ist die Zeit, die man ohnehin braucht, um alle Daten einmal zu bewegen. Selection Sort ist dann linear in der Datenmenge und nicht zu schlagen.
§6.3

Insertion Sort

Prog. 6.3 · Wächter · half-exchange · Inversionen · Eigenschaft 6.2
Prog 6.3 Insertion Sort: wie Spielkarten einordnen
„The method that people often use to sort bridge hands is to consider the elements one at a time, inserting each into its proper place among those already considered.“ Prog 6.3 verbessert Prog 6.1 an drei Stellen.
① Wächter (sentinel)Die erste Schleife bringt das kleinste Element nach a[l]. Danach kann die innere Schleife nie links aus dem Array laufen, der Test j > l entfällt.
② halber TauschStatt exch (3 Zuweisungen) wird v einmal gemerkt und größere Elemente rücken mit einer Zuweisung nach rechts.
③ früh aufhörenwhile (v < a[j-1]) stoppt, sobald v an seinem Platz ist. Deshalb ist Prog 6.3 adaptiv.
IdeeNimm das nächste Element v heraus, schiebe alle größeren Elemente links davon um eins nach rechts und setze v in die Lücke.
InvarianteVor Runde i ist a[l..i−1] sortiert (aber noch nicht endgültig: spätere Elemente können dazwischen landen).
KostenSo viele Bewegungen wie Inversionen: im Mittel ≈ N²/4, im schlechtesten Fall ≈ N²/2, bei sortierter Eingabe ≈ N.
📖 Vorlesen: „Zuerst wandert das kleinste Element als Wächter nach vorne. Dann nimm für jedes i das Element v heraus, schiebe alle größeren nach rechts und setze v in die entstandene Lücke.“
\[ \begin{aligned} &\textbf{Eigenschaft 6.2:} && \\ \Chg{M_N} &= \#\,\text{Inversionen} && \text{Jede Bewegung } a[j] = a[j-1] \text{ behebt genau eine Inversion.} \\ \text{Inversionen}_{\max} &= \binom{N}{2} = \frac{N(N-1)}{2} && \text{umgekehrt sortiert: jedes Paar steht falsch.} \\ \text{Inversionen}_{\text{avg}} &= \frac12\binom N2 = \frac{N(N-1)}{4} && \text{zufällig: jedes Paar steht mit Wahrscheinlichkeit } \tfrac12 \text{ falsch.} \\ \Res{C_N} &\approx \Chg{M_N} \approx \Res{\frac{N^2}{4}} && \text{Jeder Vergleich (bis auf den letzten pro Runde) führt zu einer Bewegung.} \\ \Res{C_N}^{\text{sortiert}} &\approx N && \text{Pro Runde nur ein Vergleich, der sofort scheitert.} \end{aligned} \]
Labor Inversionen zählen = Insertion-Sort-Kosten vorhersagen
Warum ist Insertion Sort im Mittel etwa doppelt so schnell wie Selection Sort? Beide sind quadratisch, aber Insertion braucht nur N²/4 Vergleiche, weil jedes Element im Mittel nur halb so weit nach links wandert. Bei fast sortierten Daten (Eigenschaften 6.4, 6.5) ist es sogar linear.
§6.4

Bubble Sort

Prog. 6.4 · Fig. 6.4 · Eigenschaft 6.3
Prog 6.4 Bubble Sort: das Kleinste blubbert nach links
„Keep passing through the file, exchanging adjacent elements that are out of order, continuing until the file is sorted.“ Die innere Schleife läuft von rechts nach links und nimmt das kleinste Element mit bis an Stelle i.
IdeeVergleiche Nachbarn von rechts nach links und tausche, wenn sie falsch stehen. Das Minimum des Rests wird dabei bis an Stelle i durchgereicht.
InvarianteNach Runde i stehen die i+1 kleinsten Elemente endgültig in a[l..i], wie bei Selection Sort.
KostenImmer N²/2 Vergleiche, im Mittel N²/4 und im schlechtesten Fall N²/2 Tausche (Eigenschaft 6.3).
📖 Vorlesen: „Für jedes i laufe mit j von rechts bis i+1 und vergleiche und tausche jeweils a[j−1] und a[j]. Danach steht das kleinste Restelement an Stelle i.“
\[ \begin{aligned} &\textbf{Eigenschaft 6.3:} && \\ \Res{C_N} &= \sum_{i=0}^{N-2} (N-1-i) = \Res{\frac{N(N-1)}{2}} && \text{Wie bei Selection: Runde } i \text{ hat } N-1-i \text{ compexch.} \\ \Chg{M_N} &= \#\,\text{Inversionen} && \text{Jeder Nachbartausch behebt genau eine Inversion.} \\ &\approx \frac{N^2}{4} \text{ (Mittel)}, \quad \frac{N^2}{2} \text{ (umgekehrt)} && \text{Dieselben Zahlen wie bei Insertion Sort.} \end{aligned} \]
Warum ist Bubble Sort trotzdem das langsamste der drei? Es braucht so viele Tausche (3 Zuweisungen) wie Insertion Sort halbe Tausche (1 Zuweisung) braucht, und dazu immer alle N²/2 Vergleiche. Eine Verbesserung: Hört man auf, sobald ein Durchlauf gar nicht getauscht hat, wird es auf fast sortierten Dateien schneller (Eigenschaft 6.4).

Prog. 6.5 · h-Sortieren · Inkrementfolgen · Eigenschaften 6.7–6.11
Prog 6.5 Shellsort: Insertion Sort mit großen Sprüngen
„Insertion sort is slow because the only exchanges it does involve adjacent items.“ Shellsort sortiert zuerst mit großem Abstand h und dann mit immer kleinerem, zuletzt mit h = 1. Eine Datei heißt h-sortiert, wenn jedes h-te Element (egal wo man anfängt) eine sortierte Folge bildet.
IdeeErsetze in Insertion Sort jede „1“ durch „h“. Große h bewegen Elemente weit, kleine h räumen fein auf. Der letzte Durchlauf mit h = 1 ist gewöhnliches Insertion Sort, hat aber kaum noch Arbeit.
InvarianteNach dem Durchlauf mit h ist die Datei h-sortiert. Nach einem späteren k-Durchlauf ist sie immer noch h-sortiert (Eigenschaft 6.7).
KostenMit 1 4 13 40 121 … weniger als O(N3/2) Vergleiche (Eigenschaft 6.9), praktisch viel weniger.
📖 Vorlesen: „Bestimme das größte h der Folge 1, 4, 13, 40, … das nicht größer als N/9 ist. Führe für dieses h ein Insertion Sort mit Schrittweite h aus, teile h durch 3 und wiederhole, bis h = 1 erledigt ist.“
h = 3*h+1erzeugt 1, 4, 13, 40, 121, 364, 1093, 3280, 9841 … (Knuth 1969). Das Verhältnis aufeinanderfolgender h ist etwa 1/3
h <= (r-l)/9Das größte h ist etwa N/9. Größere h bringen fast nichts, weil die Teilfolgen dann nur 1–2 Elemente haben

Prog 6.16 Selection Sort auf einer Liste
Bei Listen ist es bequemer, das Maximum zu suchen und es vorne in die Ausgabeliste einzufügen, denn vorne einfügen kostet O(1). Die Knoten werden nur umgehängt, nie kopiert.
struct node { Item item; node* next;
              node(Item x) { item = x; next = 0; } };
typedef node *link;
link findmax(link h)                             // h = Dummy-Kopf; liefert den VORGÄNGER des Maximums
  { link pmax = h;                               // erster Kandidat: der erste echte Knoten h->next
    for (link p = h->next; p->next != 0; p = p->next)
      if (pmax->next->item < p->next->item)     // ist der Nachfolger von p größer?
        pmax = p;                                //   dann ist p der neue Vorgänger des Maximums
    return pmax;
  }
link listselection(link h)
  { node dummy(0); link head = &dummy, out = 0;   // Dummy-Kopf der Eingabe, leere Ausgabe
    head->next = h;
    while (head->next != 0)                      // solange die Eingabe nicht leer ist
      { link max = findmax(head), t = max->next; // t = Knoten mit dem größten Item
        max->next = t->next;                     // t aus der Eingabe aushängen
        t->next = out; out = t;                  // t vorne an die Ausgabe hängen
      }
    return out;                                  // Ausgabe ist aufsteigend sortiert
  }

§7.1 · Theorie Teile durch Partitionieren, herrsche durch Rekursion
„Quicksort is a divide-and-conquer method for sorting. It works by partitioning an array into two parts, then sorting the parts independently.“ Im Gegensatz zu Mergesort passiert die Arbeit vor den rekursiven Aufrufen.
\[ \begin{aligned} \text{nach partition:}\quad & a[l..i-1] \le \Res{a[i]} \le a[i+1..r] && \text{Das Pivot } v = a[i] \text{ steht an seinem endgültigen Platz.} \\ \text{danach:}\quad & \texttt{quicksort}(a, l, i-1) && \text{Der linke Teil wird unabhängig sortiert,} \\ & \texttt{quicksort}(a, i+1, r) && \text{der rechte Teil ebenso. Kein Mischen nötig.} \end{aligned} \]
Prog 7.1 + 7.2 Quicksort mit Partitionierung um a[r]
„We arbitrarily choose a[r] to be the partitioning element. Next, we scan from the left end of the array until we find an element greater than the partitioning element, and we scan from the right end until we find an element less than the partitioning element.“ Beispiel aus Fig. 7.1.
IdeeWähle v = a[r]. Ein Zeiger i läuft von links, bis er ein Element ≥ v findet. Ein Zeiger j läuft von rechts, bis er ein Element ≤ v findet. Beide stehen falsch, also tauschen. Wenn sich die Zeiger kreuzen, tausche v an die Stelle i.
InvarianteKein Element links von i ist größer als v, kein Element rechts von j ist kleiner als v.
KostenEine Partition von N Elementen kostet etwa N+1 Vergleiche. Insgesamt im Mittel ≈ 2N ln N ≈ 1,39 N lg N, im schlechtesten Fall ≈ N²/2.
📖 Vorlesen: „Nimm das rechte Element als Pivot. Laufe von links, bis ein Element nicht kleiner ist, und von rechts, bis eines nicht größer ist, und tausche die beiden. Wenn sich die Zeiger kreuzen, tausche das Pivot an die Kreuzungsstelle und sortiere beide Seiten rekursiv.“

Eigenschaft 7.1 Schlechtester Fall: schon sortierte Datei
Ist die Datei schon sortiert, ist v = a[r] immer das größte Element. Jede Partition entfernt dann nur ein einziges Element.
\[ \begin{aligned} \text{Partition von } k \text{ Elementen} &: \ k+1 \text{ Vergleiche} && i \text{ läuft bis } r, j \text{ macht einen Vergleich.} \\ \text{Rest} &: \ k-1 \text{ Elemente, eine Seite leer} && \text{Das Pivot war das Maximum.} \\ \Res{C_N} &= (N+1) + N + (N-1) + \dots + 3 && \text{alle Partitionsgrößen nacheinander} \\ &= \frac{(N+1)(N+2)}{2} - 3 && \text{Gauß-Summe ohne die Glieder 1 und 2.} \\ &\approx \Res{\frac{N^2}{2}} && \textbf{Eigenschaft 7.1.} \end{aligned} \]
Noch schlimmer: Die Rekursionstiefe ist dann N. Für N = 10⁶ läuft der Aufrufstapel über. Abhilfe: zufälliges Pivot, Median-of-Three (§7.5) und den kleineren Teil zuerst (§7.3).
Eigenschaft 7.2 Mittlerer Fall: 2N ln N, von null hergeleitet
Annahme: Die Eingabe ist zufällig. Dann ist das Pivot mit gleicher Wahrscheinlichkeit 1/N das k-kleinste Element, für jedes k von 1 bis N.
\[ \begin{aligned} \Res{C_N} &= (N+1) + \frac1N\sum_{k=1}^{N}\big(C_{k-1} + C_{N-k}\big) && \text{Partition kostet } N+1. \text{ Danach Teile der Größe } k-1 \text{ und } N-k. \\ C_0 &= C_1 = 0 && \text{Anker: nichts zu sortieren.} \\ \Res{C_N} &= (N+1) + \frac2N\sum_{k=1}^{N} C_{k-1} && \text{Beide Summen sind gleich (einmal vorwärts, einmal rückwärts gelesen).} \\ N\,C_N &= N(N+1) + 2\sum_{k=1}^{N} C_{k-1} && \text{mit } N \text{ multipliziert, um den Bruch loszuwerden.} \\ (N-1)\,C_{N-1} &= (N-1)N + 2\sum_{k=1}^{N-1} C_{k-1} && \text{dieselbe Gleichung für } N-1. \\ N\,C_N - (N-1)\,C_{N-1} &= 2N + 2C_{N-1} && \text{Differenz: Die Summen heben sich bis auf ein Glied auf.} \\ N\,C_N &= (N+1)\,C_{N-1} + 2N && \text{umgestellt.} \\ \frac{C_N}{N+1} &= \frac{C_{N-1}}{N} + \frac{2}{N+1} && \text{durch } N(N+1) \text{ geteilt: Jetzt teleskopiert es.} \\ &= \frac{C_2}{3} + \sum_{k=4}^{N+1}\frac2k && \text{bis } N = 3 \text{ hinunter eingesetzt, dort gilt die Differenz noch.} \\ &= 1 + 2\Big(H_{N+1} - 1 - \tfrac12 - \tfrac13\Big) && C_2 = 3, \text{ und die Summe ist eine harmonische Zahl ohne die ersten drei Glieder.} \\ \Res{C_N} &= 2(N+1)\Big(H_{N+1} - \tfrac43\Big) && \text{exakte Lösung (Probe: } C_2 = 3,\ C_3 = 6). \\ &\approx 2N\ln N \approx \Res{1{,}39\,N\lg N} && \text{mit } H_N \approx \ln N \text{ und } \ln N = 0{,}693\lg N. \end{aligned} \]
Was die Formel sagt: Quicksort macht im Mittel nur 39 % mehr Vergleiche als der bestmögliche Fall, in dem jedes Pivot die Datei genau halbiert (\(N\lg N\)). Seine innere Schleife ist aber so kurz (ein Vergleich, ein Index-Inkrement), dass es in der Praxis meist das schnellste Verfahren ist.

§8.6

Leistung von Mergesort

Eigenschaften 8.1–8.4 · Tab. 8.1 · untere Schranke
Eigenschaft 8.1 N lg N Vergleiche, von null hergeleitet
\[ \begin{aligned} \Res{C_N} &= C_{\lfloor N/2\rfloor} + C_{\lceil N/2\rceil} + N && \text{zwei Hälften sortieren, dann } N \text{ Elemente mischen.} \\ C_1 &= 0 && \text{ein Element ist sortiert.} \\ &\textbf{Fall } N = 2^n\textbf{:} && \\ C_{2^n} &= 2\,C_{2^{n-1}} + 2^n && \text{Beide Hälften sind gleich groß.} \\ \frac{C_{2^n}}{2^n} &= \frac{C_{2^{n-1}}}{2^{n-1}} + 1 && \text{durch } 2^n \text{ geteilt (wie Formel 2.4 in Teil 1).} \\ &= \frac{C_{2^0}}{2^0} + n = n && \text{n-mal eingesetzt, } C_1 = 0. \\ \Res{C_N} &= \Res{N\lg N} && \text{mal } N = 2^n. \\ &\textbf{beliebiges } N\textbf{:} && \\ \Res{C_N} &= N\lceil\lg N\rceil + N - 2^{\lceil \lg N\rceil} && \text{exakte Lösung (Probe unten), also zwischen } N\lg N - N \text{ und } N\lg N + N. \end{aligned} \]
Warum die Zacken? Für Zweierpotenzen liegt \(C_N\) genau auf \(N\lg N\). Dazwischen ist die Rekurrenz „stückweise linear“: Jedes zusätzliche Element kostet etwa \(\lceil\lg N\rceil + 1\) Vergleiche mehr.
Eigenschaften 8.2–8.4 Speicher, Stabilität, Unempfindlichkeit
\[ \begin{aligned} &\textbf{8.2:}\ \ \text{Speicher} = N + \Mem{N} && \text{Das Hilfsarray aux ist so groß wie die Datei.} \\ &\textbf{8.3:}\ \ \text{stabil, wenn merge stabil ist} && \text{Bei Gleichheit wird aus der linken Hälfte genommen.} \\ &\textbf{8.4:}\ \ \text{Kosten unabhängig von der Eingabe} && \text{Die Aufrufstruktur hängt nur von } N \text{ ab, nicht von den Daten.} \end{aligned} \]
Quicksort oder Mergesort? Tab. 8.1: Quicksort ist auf zufälligen Daten etwa doppelt so schnell, weil seine innere Schleife kürzer ist und keine Daten ins Hilfsarray kopiert werden. Mergesort gewinnt, wenn man Garantie (N lg N immer), Stabilität oder sequentiellen Zugriff (Listen, externe Dateien) braucht.
Ergänzung Warum N lg N nicht zu schlagen ist: die untere Schranke
Das Buch nennt Mergesort „optimal“. Der Grund ist ein Standardargument über Entscheidungsbäume, das in jeder Prüfung vorkommen kann.
\[ \begin{aligned} \text{Entscheidungsbaum} &: \text{innerer Knoten} = \text{ein Vergleich } a_i < a_j\text{?} && \text{Jeder Lauf eines Verfahrens ist ein Weg von der Wurzel zu einem Blatt.} \\ \#\,\text{Blätter} &\ge N! && \text{Jede der } N! \text{ Anordnungen braucht eine eigene Umordnung.} \\ \#\,\text{Blätter} &\le 2^{h} && \text{Ein Binärbaum der Höhe } h \text{ hat höchstens } 2^h \text{ Blätter.} \\ 2^h &\ge N! && \text{beides zusammen.} \\ h &\ge \lg N! && \text{Logarithmus: } h \text{ ist die Zahl der Vergleiche im schlechtesten Fall.} \\ \lg N! &= N\lg N - N\lg e + O(\log N) && \text{Stirling-Formel.} \\ &\approx \Res{N\lg N - 1{,}44\,N} && \text{Also braucht jedes vergleichsbasierte Verfahren } \Omega(N\log N). \end{aligned} \]
Wichtig: Die Schranke gilt nur für Verfahren, die ausschließlich vergleichen. Key-Indexed Counting (§6.10) und Radixsort (Kap. 10) schauen auf die Ziffern der Schlüssel und können deshalb linear sein.

§9.3 · Theorie Zwei Reparaturen: nach oben und nach unten
fixUp (Prog 9.3) · „Beförderung“Ein Knoten ist zu groß für seinen Platz (z. B. neu unten eingefügt). Tausche ihn mit dem Elternknoten, solange dieser kleiner ist. Das Buch vergleicht das mit einem fähigen neuen Mitarbeiter, der befördert wird, bis sein Chef besser ist.
fixDown (Prog 9.4) · „Degradierung“Ein Knoten ist zu klein für seinen Platz (z. B. neue Wurzel). Tausche ihn mit dem größeren Kind, solange dieses größer ist. Zwei Ausgänge: unten angekommen oder Heap-Bedingung erfüllt.
template <class Item>
void fixUp(Item a[], int k)
  {
    while (k > 1 && a[k/2] < a[k])              // nicht an der Wurzel und Eltern kleiner?
      { exch(a[k], a[k/2]); k = k/2; }            // tauschen, eine Ebene höher weitermachen
  }
template <class Item>
void fixDown(Item a[], int k, int N)
  {
    while (2*k <= N)                               // solange k mindestens ein Kind hat
      { int j = 2*k;                               // j = linkes Kind
        if (j < N && a[j] < a[j+1]) j++;           // rechtes Kind existiert und ist größer?
        if (!(a[k] < a[j])) break;                 // k nicht kleiner als das größere Kind: fertig
        exch(a[k], a[j]); k = j;                   // tauschen, eine Ebene tiefer weitermachen
      }
  }

Eigenschaften 9.4–9.6 Warum der Aufbau linear ist
Man könnte meinen, N fixDown-Aufrufe kosten N lg N. Aber die meisten Teilheaps sind winzig: Die Hälfte der Knoten sind Blätter, ein Viertel hat Höhe 1, und nur die Wurzel hat die volle Höhe.
\[ \begin{aligned} &\textbf{Eigenschaft 9.4:}\ \text{Aufbau in linearer Zeit} && \\ N &= 2^n - 1 && \text{vollständiger Baum mit } n \text{ Ebenen, zum Beispiel } N = 127,\ n = 7. \\ \text{Knoten mit Höhe } k &: \ 2^{\,n-k-1} && \text{32 Teilheaps der Größe 3, 16 der Größe 7, 8 der Größe 15, …} \\ \text{Beförderungen} &\le \sum_{1 \le k < n} k\cdot 2^{\,n-k-1} && \text{ein fixDown ab Höhe } k \text{ tauscht höchstens } k\text{-mal.} \\ &= 2^n - n - 1 && \text{Summenformel (Probe } n = 3:\ 1\cdot2 + 2\cdot1 = 4 = 8-3-1). \\ &< \Res{N} && \text{also höchstens } N \text{ Tausche und } 2N \text{ Vergleiche.} \\ &\textbf{Eigenschaft 9.5:}\ \Res{C_N < 2N\lg N} && \text{Abbau: } N-1 \text{ fixDown, jeder } \le 2\lg N \text{ Vergleiche.} \\ &\textbf{Eigenschaft 9.6:}\ k \text{ größte finden} && \text{Heap bauen } (< 2N) \text{ plus } k\text{-mal getmax } (2k\lg N). \\ & && \text{linear, wenn } k \text{ klein ist, sonst } O(N\log N). \end{aligned} \]
Heapsort in der Praxis: Garantiert \(N\lg N\) wie Mergesort, braucht aber keinen Zusatzspeicher. Auf zufälligen Daten ist es trotzdem etwa doppelt so langsam wie Quicksort, weil fixDown weit entfernte Array-Stellen anspringt und doppelt so viele Vergleiche braucht.

§10.1

§10.1 · Bauplan Ein Schlüssel ist eine Folge von Ziffern zur Basis R
„Radix-sorting methods … process the keys in small pieces“. Statt ganze Schlüssel zu vergleichen, schauen sie auf einzelne Ziffern: Bits (R = 2), Bytes (R = 256) oder Zeichen. Damit gilt die N lg N-Schranke aus §8.6 nicht mehr.
const int bitsword = 32;                       // w: Bits pro Schlüssel
const int bitsbyte = 8;                        // Bits pro Ziffer ("Byte")
const int bytesword = bitsword/bitsbyte;       // w / lg R: Ziffern pro Schlüssel
const int R = 1 << bitsbyte;                   // Radix R = 2^bitsbyte = 256
inline int digit(long A, int B)                // B-te Ziffer von links (B = 0 ist die höchste)
  { return (A >> bitsbyte*(bytesword-B-1)) & (R-1); }
inline int digit(char* A, int B)               // für C-Strings: die Ziffer ist das B-te Zeichen
  { return A[B]; }
\[ \begin{aligned} \Idx{\text{digit}}(A, B) &= \big(A \gg \text{bitsbyte}\cdot(\text{bytesword}-B-1)\big)\ \&\ (R-1) && \text{erst nach rechts schieben, bis die Ziffer B ganz unten steht,} \\ & && \text{dann alle höheren Bits wegmaskieren } (R-1 = 11\dots1_2). \\ \text{Schlüsselgröße} &= w \text{ Bits} = \frac{w}{\lg R} \text{ Ziffern} && \text{je größer } R, \text{ desto weniger Ziffern, aber desto mehr Zähler.} \end{aligned} \]
📖 Vorlesen: „Ein Schlüssel aus w Bits besteht aus w durch lg R Ziffern zur Basis R. digit(A, B) holt die B-te Ziffer von links, indem es A passend nach rechts schiebt und mit R−1 maskiert.“
§10.2

Binärer Quicksort

Prog. 10.1 · Fig. 10.2 · 10.3 · Eigenschaft 10.2
Prog 10.1 Partitionieren nach einem Bit statt nach einem Pivot
Die Buchstaben sind mit 5 Bits codiert (A = 00001, B = 00010, …, Z = 11010, Fig. 10.3). Partitioniert wird nach Bit d: links alle mit 0, rechts alle mit 1. Dann rekursiv mit dem nächsten Bit.
IdeeWie Quicksort, aber die Frage heißt nicht „kleiner als v?“, sondern „ist Bit d gleich 0?“. i sucht von links eine 1, j von rechts eine 0, dann tauschen.
InvarianteLinks von i haben alle Schlüssel Bit d = 0, rechts von j alle Bit d = 1. Alle Schlüssel eines Aufrufs stimmen in den Bits 0 … d−1 überein.
KostenIm Mittel etwa N lg N untersuchte Bits (Eigenschaft 10.2), höchstens N·w.
📖 Vorlesen: „Schiebe i nach rechts, solange Bit d eine Null ist, und j nach links, solange Bit d eine Eins ist, und tausche. Wenn sich die Zeiger treffen, sortiere den Null-Teil und den Eins-Teil rekursiv nach dem nächsten Bit.“
Unterschied zu Quicksort: Kein Element wird bei der Partitionierung „endgültig“ platziert, und die Teile können sehr ungleich sein (etwa wenn alle Schlüssel mit 0 beginnen). Dafür ist die Rekursionstiefe höchstens w, und gleiche Schlüssel kosten keine Extra-Arbeit.
§10.3

MSD-Radixsort

Prog. 10.2 · Fig. 10.7 · Eigenschaften 10.3 · 10.4
Prog 10.2 Most-Significant-Digit: in R Fächer verteilen, dann jedes Fach rekursiv
Das Verteilen ist Key-Indexed Counting (Prog 6.17) auf die Ziffer d. Danach liegen alle Wörter mit gleichem ersten Buchstaben in einem zusammenhängenden Fach, und jedes Fach wird nach dem zweiten Buchstaben sortiert. Beispielwörter aus Fig. 10.7.
IdeeZähle, wie viele Schlüssel jede Ziffer d haben, verteile sie stabil in R Fächer und sortiere jedes Fach rekursiv mit Ziffer d+1.
InvarianteNach der Verteilung stehen die Fächer in der richtigen Reihenfolge. Innerhalb eines Faches stimmen alle Schlüssel in den ersten d+1 Ziffern überein.
KostenJeder Aufruf kostet mindestens 2N + 2R (Eigenschaft 10.3). Viele kleine Fächer machen die R Zähler teuer, deshalb der Cutoff M mit Insertion Sort.
📖 Vorlesen: „Zähle die Ziffern an Stelle d, bilde Teilsummen, verteile die Schlüssel nach aux und kopiere zurück. Dann sortiere jedes der R Fächer rekursiv nach der nächsten Ziffer.“
\[ \begin{aligned} &\textbf{Eigenschaft 10.3:} && \\ \text{ein Aufruf} &\ge 2N + 2R && \text{zwei Durchläufe über die Schlüssel, zwei über die Zähler.} \\ &\textbf{Eigenschaft 10.4:} && \\ \text{zufällige Schlüssel},\ R &< N: \quad \Res{\approx N\log_R N} && \text{Nach } \log_R N \text{ Ziffern sind die Fächer im Mittel nur noch 1 Element groß.} \end{aligned} \]
Das Problem mit leeren Fächern: Für R = 256 und eine Teildatei mit 3 Schlüsseln kostet schon das Löschen der 256 Zähler mehr als das Sortieren selbst. Abhilfen: Cutoff M für kleine Dateien (Insertion Sort), kleineres R, oder 3-Wege-Radix-Quicksort.
§10.4

Drei-Wege-Radix-Quicksort

Prog. 10.3 · Fig. 10.10 · Eigenschaft 10.5
Prog 10.3 Quicksort auf einem Zeichen, mit drei Teilen
„This MSD radix sort is essentially the same code as quicksort with three-way partitioning (Program 7.5)“, nur dass das Pivot ein Zeichen v = ch(a[r]) an Stelle d ist. Der mittlere Teil (gleiches Zeichen) wird mit dem nächsten Zeichen weitersortiert.
IdeeTeile nach dem Zeichen an Stelle d in < v, = v und > v. Linker und rechter Teil bleiben bei Stelle d, der mittlere geht zu d+1. Ist v das Endezeichen '\0', ist der mittlere Teil fertig.
InvarianteAlle Schlüssel eines Aufrufs stimmen in den ersten d Zeichen überein.
KostenIm Mittel etwa 2N ln N Zeichenvergleiche (Eigenschaft 10.5), unabhängig von R. Ideal für Strings mit langen gemeinsamen Präfixen.
#define ch(A) digit(A, d)                            // Zeichen an Stelle d
template <class Item>
void quicksortX(Item a[], int l, int r, int d)
  {
    int i, j, k, p, q; int v;
    if (r-l <= M) { insertion(a, l, r); return; }    // kleine Dateien: Insertion Sort
    v = ch(a[r]); i = l-1; j = r; p = l-1; q = r;      // Pivot-ZEICHEN v
    while (i < j)
      {
        while (ch(a[++i]) < v) ;                       // wie Prog 7.5, nur mit ch()
        while (v < ch(a[--j])) if (j == l) break;
        if (i > j) break;
        exch(a[i], a[j]);
        if (ch(a[i])==v) { p++; exch(a[p], a[i]); }    // gleiche Zeichen an die Ränder
        if (v==ch(a[j])) { q--; exch(a[j], a[q]); }
      }
    if (p == q)                                        // ALLE haben Zeichen v an Stelle d:
      { if (v != '\0') quicksortX(a, l, r, d+1);       //   einfach eine Stelle weiter
        return; }
    if (ch(a[i]) < v) i++;
    for (k = l; k <= p; k++, j--) exch(a[k], a[j]);   // Gleiche in die Mitte
    for (k = r; k >= q; k--, i++) exch(a[k], a[i]);
    quicksortX(a, l, j, d);                            // kleineres Zeichen: gleiche Stelle d
    if ((i == r) && (ch(a[i]) == v)) i++;
    if (v != '\0') quicksortX(a, j+1, i-1, d+1);       // gleiches Zeichen: nächste Stelle
    quicksortX(a, i, r, d);                            // größeres Zeichen: gleiche Stelle d
  }
📖 Vorlesen: „Nimm das Zeichen an Stelle d des rechten Schlüssels als Pivot. Teile in kleiner, gleich und größer. Sortiere den kleineren und den größeren Teil an derselben Stelle weiter, den gleichen Teil an der nächsten Stelle.“
\[ \begin{aligned} &\textbf{Eigenschaft 10.5:} && \\ \Res{C_N} &\approx 2N\ln N \ \text{Zeichenvergleiche} && \text{wie Quicksort, aber jeder Vergleich betrifft nur ein Zeichen.} \\ \text{Quicksort auf Strings} &\approx 2N\ln N \cdot (\text{Präfixlänge}) && \text{jeder volle String-Vergleich läuft über das gemeinsame Präfix.} \end{aligned} \]
§10.5

LSD-Radixsort

Prog. 10.4 · Fig. 10.14 · Eigenschaft 10.6
Prog 10.4 Least-Significant-Digit: von hinten nach vorne, jedes Mal stabil
Das ist das Verfahren der alten Lochkarten-Sortiermaschinen: erst nach der letzten Spalte sortieren, dann nach der vorletzten und so weiter. Das funktioniert nur, weil jeder Durchlauf stabil ist. Beispielwörter aus Fig. 10.14.
IdeeFür d von der letzten Ziffer bis zur ersten: Key-Indexed Counting nach Ziffer d über die ganze Datei. Keine Rekursion, keine Fächer-Verwaltung.
InvarianteNach dem Durchlauf für Ziffer d ist die Datei nach den letzten bytesword−d Ziffern sortiert. Schlüssel mit gleicher Ziffer d behalten wegen der Stabilität ihre Ordnung aus den früheren Durchläufen.
Kostenw/lg R Durchläufe, je 2N + 2R Schritte (Eigenschaft 10.6). Linear in N für feste Schlüssellänge.
📖 Vorlesen: „Für d von der letzten Stelle bis zur ersten: Zähle die Ziffern an Stelle d, bilde Teilsummen, verteile alle Schlüssel stabil nach aux und kopiere zurück.“
\[ \begin{aligned} &\textbf{Eigenschaft 10.6:} && \\ \text{Durchläufe} &= \frac{w}{\lg R} && \text{eine pro Ziffer.} \\ \text{je Durchlauf} &= 2N + 2R && \text{zählen und verteilen über die Schlüssel, löschen und aufsummieren über die Zähler.} \\ \Res{T(N)} &= \frac{w}{\lg R}\,(2N + 2R) && \text{bei 32-Bit-Schlüsseln und } R = 2^{16}: \text{ zwei Durchläufe, also etwa } 4N. \\ \Mem{\text{Speicher}} &= N + R && \text{Puffer aux und die Zähler.} \end{aligned} \]

§11.1 · Theorie Nicht-adaptiv: immer dieselben Vergleiche, egal welche Daten
Ein Verfahren heißt nicht-adaptiv, wenn die Folge der compexch-Operationen nur von N abhängt, nicht von den Schlüsseln. Dann kann man es als festes Netz aus Komparatoren bauen, in Hardware oder parallel auf vielen Prozessoren.
template <class Item>
void shuffle(Item a[], int l, int r)             // perfektes Mischen (wie Spielkarten)
  { int i, j, m = (l+r)/2;
    static Item aux[maxN];
    for (i = l, j = 0; i <= r; i+=2, j++)
      { aux[i] = a[l+j]; aux[i+1] = a[m+1+j]; }  // abwechselnd aus erster und zweiter Hälfte
    for (i = l; i <= r; i++) a[i] = aux[i];
  }
template <class Item>
void unshuffle(Item a[], int l, int r)           // Umkehrung: gerade Stellen nach vorne
  { int i, j, m = (l+r)/2;
    static Item aux[maxN];
    for (i = l, j = 0; i <= r; i+=2, j++)
      { aux[l+j] = a[i]; aux[m+1+j] = a[i+1]; }  // Stelle l+2j nach vorne, l+2j+1 nach hinten
    for (i = l; i <= r; i++) a[i] = aux[i];
  }
\[ \begin{aligned} &\textbf{Eigenschaft 11.1 (0-1-Prinzip):} && \\ & \text{Sortiert ein nicht-adaptives Programm alle Eingaben aus 0 und 1,} && \text{Man muss nur } 2^N \text{ Eingaben prüfen} \\ & \text{dann sortiert es alle Eingaben.} && \text{statt } N! \text{ Permutationen.} \\ &\textbf{Eigenschaft 11.2:} && \\ & \text{Batchers Odd-Even-Merge ist ein korrektes Mischverfahren.} && \text{Beweis mit dem 0-1-Prinzip: vier Fälle, je nachdem ob} \\ & && \text{die Anzahl } i, j \text{ der Nullen in den Hälften gerade oder ungerade ist.} \end{aligned} \]
Prog 11.2 Odd-Even-Merge rekursiv
Gegeben: zwei sortierte Hälften (N eine Zweierpotenz). ① unshuffle trennt gerade und ungerade Positionen. ② Beide Teile werden rekursiv gemischt. ③ shuffle verzahnt sie wieder. ④ Eine letzte Reihe compexch zwischen Nachbarn repariert alles, was noch falsch steht.
IdeeDie Elemente an geraden Positionen beider Hälften bilden zusammen fast die richtige Folge, ebenso die an ungeraden. Nach dem Verzahnen ist jedes Element höchstens eine Stelle von seinem Ziel entfernt.
InvarianteNach merge(a, l, m, r) ist a[l..r] sortiert, vorausgesetzt a[l..m] und a[m+1..r] waren es.
KostenM(N) = 2M(N/2) + N/2 − 1 Komparatoren, also ≈ (N lg N)/2 für das Mischen. Nur lg N parallele Schritte.
📖 Vorlesen: „Bei zwei Elementen: einmal compexch. Sonst trenne gerade und ungerade Stellen, mische beide Teile rekursiv, verzahne sie wieder und vergleiche zum Schluss jedes Nachbarpaar ab Stelle l+1.“
§11.2

Sortiernetzwerke

Prog. 11.4 · Fig. 11.7 · Eigenschaft 11.3
Prog 11.4 · Fig 11.7 Das Batcher-Sortiernetz zum Ausprobieren
Jede waagerechte Linie trägt ein Element, jeder senkrechte Strich ist ein Komparator: Oben kommt das Kleinere heraus, unten das Größere. Komparatoren in derselben Spalte berühren verschiedene Linien und können gleichzeitig arbeiten.
template <class Item>
void batchersort(Item a[], int l, int r)
  { int N = r-l+1;
    for (int p = 1; p < N; p += p)                          // Phase: Blöcke der Größe 2p entstehen
      for (int k = p; k > 0; k /= 2)                        // Abstand der Komparatoren: p, p/2, p/4 bis 1
        for (int j = k%p; j+k < N; j += (k+k))              // Startpunkte der Komparator-Gruppen
          for (int i = 0; i < N-j-k; i++)                   // Buch; korrekt für Batcher: i < k
            if ((j+i)/(p+p) == (j+i+k)/(p+p))               // beide Enden im selben 2p-Block?
              compexch(a[l+j+i], a[l+j+i+k]);
  }
Klick auf einen Komparator schaltet ihn aus (grau). Der 0-1-Test zeigt dann sofort eine Eingabe aus Nullen und Einsen, die nicht mehr sortiert wird. Genau so beweist man mit Eigenschaft 11.1, dass ein Netz korrekt ist oder nicht.
\[ \begin{aligned} &\textbf{Eigenschaft 11.3:} && \\ \#\,\text{Komparatoren} &\approx \frac{N(\lg N)^2}{4} && \text{genauer: für } N = 8 \text{ sind es 19, für } N = 16 \text{ sind es 63.} \\ \#\,\text{parallele Schritte} &\approx \frac{(\lg N)^2}{2} && \text{genauer } \tfrac12\lg N(\lg N+1): \text{ Merge-Netz } k \text{ braucht } k \text{ Schritte, } 1+2+\dots+\lg N. \end{aligned} \]
Zur gedruckten Schleifengrenze: Mit i < N-j-k erzeugt Prog 11.4 zusätzliche, teils doppelte Komparatoren (N = 8: 46 statt 19, N = 16: 280 statt 63). Das Ergebnis ist trotzdem sortiert (der 0-1-Test besteht), aber es ist nicht mehr das Batcher-Netz aus Fig. 11.7 und die Anzahl passt nicht zu Eigenschaft 11.3. Mit i < k (und der Bedingung j+i+k < N, die dann die Schleife nicht mehr garantiert) entstehen genau die Batcher-Komparatoren.

§11.3 · Theorie Wenn die Datei nicht in den Speicher passt
Das Kostenmodell ändert sich völlig: Ein Zugriff auf Band oder Platte ist tausendmal teurer als ein Vergleich. Man zählt deshalb Durchläufe (passes) über die ganze Datei.
① Runs erzeugenLies jeweils M Datensätze in den Speicher, sortiere sie intern (Kap. 6–10) und schreibe sie als sortierten Run auf ein Band. Mit Ersetzungsauswahl (Heap) werden die Runs im Mittel 2M lang.
② P-Wege-MischenMische P Runs gleichzeitig mit einer Prioritätswarteschlange der Größe P (Kap. 9) zu einem P-mal längeren Run. Bei 2P Bändern wechseln Eingabe- und Ausgabebänder ab.
③ PolyphasenMit wenigen Bändern (z. B. 3) verteilt man die Runs nach verallgemeinerten Fibonacci-Zahlen, damit kein Band leer herumsteht.
\[ \begin{aligned} &\textbf{Eigenschaft 11.4:} && 2P \text{ Bänder, Speicher für } M \text{ Datensätze, } P\text{-Wege-Mischen:} \\ \Res{\text{Durchläufe}} &\approx 1 + \Big\lceil \log_P \frac{N}{M} \Big\rceil && 1 \text{ Durchlauf für die Runs, dann jeder Mischdurchlauf teilt die Run-Zahl durch } P. \\ &\textbf{Eigenschaft 11.5:} && \text{Ersetzungsauswahl erzeugt bei zufälligen Schlüsseln Runs der Länge } \approx 2M. \\ &\textbf{Eigenschaft 11.6:} && 3 \text{ Bänder, Ersetzungsauswahl, Polyphasen-Mischen:} \\ \Res{\text{effektive Durchläufe}} &\approx 1 + \Big\lceil \log_\phi \frac{N}{2M} \Big\rceil \Big/ \phi && \phi = 1{,}618 \dots \text{ (goldener Schnitt).} \\ &\textbf{Eigenschaft 11.7:} && \text{Datei in } N/M \text{ Blöcke der Größe } M \text{ teilen, jeden sortieren, dann ein Sortiernetz} \\ & && \text{aus mischenden Komparatoren (merge statt compexch) anwenden.} \\ &\textbf{Eigenschaft 11.8:} && \text{Mit } P \text{ Prozessoren und Batchers Netz: etwa } \frac{(\lg P)^2}{2} \text{ parallele Schritte.} \end{aligned} \]
Eigenschaft 11.5 · Labor Ersetzungsauswahl: warum die Runs doppelt so lang werden
Ein Heap der Größe M hält die nächsten Kandidaten. Man gibt immer das kleinste Element aus, das noch in den aktuellen Run passt (≥ dem zuletzt ausgegebenen), und liest dafür das nächste Element ein. Ist es kleiner als das zuletzt ausgegebene, wird es für den nächsten Run markiert.
Intuition (Schneepflug-Bild aus der Literatur): Man stellt sich die Werte als Schnee auf einer Kreisbahn vor. Der Pflug räumt, während neuer Schnee gleichmäßig fällt. Im Gleichgewicht liegt vor dem Pflug doppelt so viel Schnee wie im Speicher Platz hat. Bei fast sortierter Eingabe wird ein einziger langer Run erzeugt, bei umgekehrter nur Runs der Länge M.

Schema A Drei Beispiele mit steigender Schwierigkeit
① leicht · doppelte Schleife 
int cnt = 0;
for (i = 0; i < N-1; i++)
  for (j = i+1; j < N; j++)
    cnt++;               // ein Vergleich
① cnt++ zählt. ② zwei Schleifen, keine Rekursion. ③ unabhängig von den Daten. \[ \begin{aligned} \Res{C} &= \sum_{i=0}^{N-2}(N-1-i) && \text{innere Schleife} \\ &= \frac{N(N-1)}{2} && \text{Gauß} \end{aligned} \] Θ(N²): Selection Sort
② mittel · Teilen und Mischen 
int f(int l, int r)
  { if (r <= l) return 0;
    int m = (l+r)/2;
    return f(l, m) + f(m+1, r)
         + (r-l+1);      // Mischkosten
  }
① r−l+1 pro Aufruf. ② zwei Aufrufe mit halber Größe. ③ unabhängig. \[ \begin{aligned} \Res{C_N} &= 2C_{N/2} + N && \text{Formel 2.4} \\ &= N\lg N && N = 2^n \end{aligned} \] Θ(N log N): Mergesort
③ schwer · Heap bauen 
int cnt = 0;
for (k = N/2; k >= 1; k--)
  for (j = k; 2*j <= N; j = 2*j)
    cnt++;               // höchstens ein Tausch
① cnt++ = Höhe des Knotens k. ② Schleife mal Weg nach unten. ③ worst case gezählt. \[ \begin{aligned} \Res{C} &= \sum_{k=1}^{n-1} k\,2^{n-k-1} && N = 2^n-1 \\ &= 2^n - n - 1 < N && \text{Eig. 9.4} \end{aligned} \] Θ(N), nicht N lg N!
Die Lehre aus Beispiel ③: „Eine Schleife über N mal eine innere Schleife bis lg N“ ergibt nur eine obere Schranke N lg N. Wer genauer zählt, sieht, dass die meisten Knoten weit unten stehen und kurze Wege haben. Dasselbe Argument taucht in Teil 4 bei den Suchbäumen wieder auf.
